# Session Handoff: 2026-04-29_0356_summary

## Overview
Investigated and resolved a series of cascading CORS and 404 errors occurring in the Admin Panel deployed on GitHub Pages when communicating with the Render backend.

## Key Changes
1. **Frontend API Fixes:**
   - Fixed `apiGetSubscriptions` in `frontend/src/lib/api.ts` to call `/api/subscriptions` instead of the non-existent `/api/admin/subscriptions`.
   - Fixed `DiscordLabTab.tsx` to call `/api/admin/guides` instead of the non-existent `/api/guides`.

2. **Backend Database Concurrency & Timezone Fixes:**
   - In `backend/routers/admin.py`, the `admin_stats` endpoint was running multiple queries concurrently using `asyncio.gather(session.execute(...))`. This violated SQLAlchemy's AsyncSession concurrency constraints and caused 500 errors (which were misinterpreted by the browser as CORS errors due to lack of CORS headers on the 500 response). Rewrote queries to execute sequentially.
   - In `backend/database.py`, the `get_daily_analytics` function was comparing timezone-aware `ViewLog.viewed_at` with naive `datetime.now()`, causing `DataError` crashes in Postgres. Fixed by using `datetime.now(timezone.utc)`.

## Technical Debt / Bugs Discovered
- `BaseHTTPMiddleware` and `CORSMiddleware` ordering inside FastAPI can swallow CORS headers on 500/404 responses if exceptions occur within endpoints. Proper exception handling at the router level or using custom exception handlers that attach CORS headers can prevent confusing browser errors.

- Ensure any further admin endpoints properly await DB sessions sequentially.
